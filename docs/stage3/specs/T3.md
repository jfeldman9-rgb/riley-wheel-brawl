## 1. Goal and dependencies

- Goal: `?stage=3&s3=1` builds a lit Caemlyn backdrop (day and night far plates, two mid plates, three floors), a sun

  `timeOfDay(camX, keys)`. T3 also **owns all Stage 3 loading** (`queueStage3`, including the char atlases). No
  enemies, hazards or boss logic (T4–T7).
- **T1 (landed):** `src/stages.js` has `STAGE3` (`:183-221`, `kit: null`, `skipBoss {zoneI 2, x 3990, camX 3500}`,
  `ribbon {zone 1, wave 0}`), `STAGE_CHARS[3]` (`:45`), `SHARED_TEXTURES` / `STAGE_TEXTURES[3]` (`:49-55`).
  `src/stage1.js` wires `STAGES[3].queue = queueStage3Stub` (`:69-75`), builds `new this.stageDef.kit(this)` (`:133`),
  and calls `queueCharPages(this, stageDef.chars)` then `stageDef.queue(this)` in `preload` (`:105-106`).
- **T2:** placeholders in `assets/bg3/*`, `assets/story/story3_panel_{1,2,3}.jpg`, `assets/stage3/chars/*` (each
  `anims.json` has `"dir": "assets/stage3/chars"`), `assets/stage3/props/*`, `assets/stage3/ui/fade-portrait.webp`.
- Unblocks T4/T5/T6 (atlases load in the browser) and T7 (hazards hang off this kit).

### 3.2 Pure helpers
- `lerpColor(a, b, u)`: per channel `Math.round(ca + (cb - ca) * u)`, packed back to `0xRRGGBB`.
- `timeOfDay(camX, keys)`; `keys` = `lights.json.timeKeys` `[{ x, ambient, farMix, sunI }]`, x strictly increasing.
  - Empty/missing → `{ ...TOD_FALLBACK }`. One key → that key with `t: 0`, `torchK: 0`.
  - `t = clamp((camX - keys[0].x) / (keys.at(-1).x - keys[0].x), 0, 1)`; `torchK = t`.
  - Segment `i` with `keys[i].x ≤ camX ≤ keys[i+1].x` (clamped to the end keys outside the range),
    `u = (camX - keys[i].x) / (keys[i+1].x - keys[i].x)`; `ambient = lerpColor(hex(k0.ambient), hex(k1.ambient), u)`;
    `farMix`, `sunI` linear.
  - Returns a fresh `{ t, ambient, farMix, sunI, torchK }`. No Phaser, no scene.

## 6. Edge cases

- **Restart in Stage 3** (game over, `continueGame`, title reselect): Phaser clears lights and objects; `create()`
  builds a new kit. Sun, torch latches and emitters are per instance, never module-level. `build()` ignores the stale
  `s.camX` (§3.4), so a restart after the boss has a full sun again.
- **Stage 2 → 3** (`STAGE2.next` with `s3=1`): `releaseStage(3)` drops `arrow`/`ribbon`/`byar` pages, `queueStage3`
  re-queues the two textures; `fireCap` 5 from the barn is reset to 4.
- **`?lit=0` / governor level 4** (`main.js:47`): `setBackdropLit(false)` sets `ambientUnlit`; `update` keeps it.
- **Lights off (Digit1):** ambient stays white, sun intensity 0; fires are zeroed by `stage1.js:658`.
- **Pause and hit-stop:** `update` returns before `kit.update` (`stage1.js:661-666`), so ramps freeze. Correct.
- **Missing JSON** (the headless helper has no `plates3`/`lights3`, `tests/helpers/stage1-simulation.mjs:29`): the
  kit still builds: no torches, no sun, `TOD_FALLBACK` ambient, cap 4, one floor.
- **Rounding:** every timeKey channel is non-increasing (dusk `0x3a3a52`), so rounded luminance is exactly monotone.
- **Light budget:** ≤ 4 torch lights visible; the sun is gone by the boss zone; unlit torches own no light. T7
  asserts the §2.5 worst case.

## 9. Discrepancies with PLAN.md and open questions

1. **Night key x.** PLAN's example puts night at x 4000, but the boss camera locks at 3920. The spec uses 3900 so the
   sun reaches 0 in the boss zone, also from `skipBoss.camX` 3500 (§4).
2. **Dusk colour.** PLAN's `0x3a3a58` has a blue channel above sunset's `0x52`, which can break exact monotone
   luminance after rounding. The spec uses `0x3a3a52`.
3. **`timeKeys` shape.** Each key carries `farMix` and `sunI`; `torchK` is defined as `t` (PLAN does not define it).
4. **Kit reuse.** `Stage3Kit extends Stage2Kit`: Stage 3 waves have zealots and archers, and `whitecloaks.js:137-139`
   / `bot.js:44-60` call methods and read `threats()` fields without per-method guards.
5. **S8 scope.** Only the Stage 3 kit resets `fireCap` (in `build()`, not `create()` as PLAN says). Resetting it in
   `create()` for every stage would change Stage 1 after a Stage 2 rage (`stage1.js:714` uses `this.fireCap ||`).
   Left for Jason or T15.
6. **Loading lives in T3.** `queueStage3` and the `m.dir` change are T3's; T4, T5, T6 must not duplicate them.
   T11's `stage-query-probe` stubs `load.on` as a no-op, so it will not see atlas pages.
7. **Texture lists.** No `STAGE_TEXTURES` / `SHARED_TEXTURES` change (§3.3): `ribbon`/`arrow` are re-queued instead
   (one extra fetch on 2 → 3, normally from the HTTP cache), and `fadePortrait` stays resident like the boot
   portraits. If Jason wants it released, that needs a T2 test 6 change or a new release hook (T9/T15).
8. **`build()` and stale `camX`.** New with T1's `create()` order (`:133`, `:148`, `:158`, `:184`); PLAN assumed
   `build()` could read the camera. Covered by test 4.
